# Linux — Users and Groups

## 1. Why Users & Groups Matter

Linux is a **multi-user operating system**. Every process and every file has an owner and permissions.

Users and Groups are fundamental to:

- managing access to files,
- system security,
- running services,
- using `sudo`,
- server administration.

---

## 2. Users

Every user has:

- **username** — the user's name,
- **UID** — unique user ID,
- **GID** — primary group ID,
- **home directory** — e.g. `/home/dominik`,
- **shell** — e.g. `/bin/bash`.

Check the current user:

```bash
whoami
```

Get more information:

```bash
id
```

Example:

```text
uid=1000(dominik) gid=1000(dominik) groups=1000(dominik),27(sudo)
```

The important fields:

- `uid` → your user ID,
- `gid` → your primary group ID,
- `groups` → all groups you belong to.

---

## 3. Root

`root` is the administrator account.

It has almost complete control over the system, so you should not work as root all the time.

Check root:

```bash
id root
```

Start a root shell:

```bash
sudo -i
```

Run a single command as root:

```bash
sudo command
```

Example:

```bash
sudo apt update
```

**Best practice:** use `sudo` only when necessary.

---

## 4. Important Files

### `/etc/passwd`

Contains basic information about users.

```bash
cat /etc/passwd
```

Example entry:

```text
dominik:x:1000:1000:Dominik:/home/dominik:/bin/bash
```

Fields:

```text
username : password-placeholder : UID : GID : description : home : shell
```

> Passwords are not stored directly in `/etc/passwd`.

### `/etc/shadow`

Contains password hashes and password aging information.

Access is restricted:

```bash
sudo cat /etc/shadow
```

### `/etc/group`

Contains information about groups:

```bash
cat /etc/group
```

---

## 5. Groups

A group lets you grant access to multiple users at once.

Instead of managing permissions separately:

```text
user1 → access
user2 → access
user3 → access
```

you can create:

```text
developers
├── user1
├── user2
└── user3
```

and grant access to the group.

Check a user's groups:

```bash
groups
```

or:

```bash
id
```

---

## 6. Primary and Supplementary Groups

Every user has a **primary group**.

A user can also belong to multiple **supplementary groups**.

Example:

```text
User: dominik

Primary group:
└── dominik

Supplementary groups:
├── sudo
├── docker
└── developers
```

Check:

```bash
id dominik
```

---

## 7. Creating a User

A convenient way to create a user on Debian/Ubuntu is:

```bash
sudo adduser username
```

Example:

```bash
sudo adduser devuser
```

You may also encounter:

```bash
sudo useradd username
```

`useradd` is a lower-level tool and often requires you to specify additional options explicitly.

---

## 8. Removing a User

Remove a user:

```bash
sudo deluser username
```

Remove a user together with their home directory:

```bash
sudo deluser --remove-home username
```

Before removing a user, make sure they do not own important files or have important processes running.

---

## 9. Changing Passwords

Change your own password:

```bash
passwd
```

Change another user's password:

```bash
sudo passwd username
```

Example:

```bash
sudo passwd devuser
```

---

## 10. Creating a Group

Create a group:

```bash
sudo groupadd developers
```

Check the group:

```bash
getent group developers
```

---

## 11. Adding a User to a Group

The most important command:

```bash
sudo usermod -aG group username
```

Example:

```bash
sudo usermod -aG docker dominik
```

### Very Important: `-aG`

`-a` = **append** — add the group without removing existing supplementary groups.

`-G` = specify supplementary groups.

Without `-a`, you can accidentally overwrite the user's existing supplementary group memberships.

After changing group membership, you often need to **log out and log back in** so the current session recognizes the new membership.

Check:

```bash
groups dominik
```

---

## 12. Removing a User from a Group

On Debian/Ubuntu:

```bash
sudo deluser username group
```

Example:

```bash
sudo deluser dominik docker
```

Another option:

```bash
sudo gpasswd -d username group
```

---

## 13. `sudo` and the `sudo` Group

On Debian/Ubuntu, a user in the `sudo` group can run commands with administrative privileges.

Check your groups:

```bash
groups
```

Add a user to the `sudo` group:

```bash
sudo usermod -aG sudo username
```

Then log out and log back in.

> On other distributions, the administrative group may have a different name, such as `wheel`.

---

## 14. `sudoers`

The main `sudo` configuration file is:

```text
/etc/sudoers
```

**Do not edit this file with a normal text editor.**

Use:

```bash
sudo visudo
```

`visudo` checks the syntax and reduces the risk of breaking the `sudo` configuration.

Additional configuration files are commonly stored in:

```text
/etc/sudoers.d/
```

---

## 15. Service Accounts

Not every user account belongs to a human.

Linux systems often have users dedicated to running services.

Examples:

```text
www-data
postgres
mysql
nginx
```

The idea is:

```text
service → dedicated user → limited permissions
```

This is important for security.

If an application is compromised, it should not automatically have full root privileges.

## 16. Checking Users

List users:

```bash
cat /etc/passwd
```

Query a specific user:

```bash
getent passwd username
```

Example:

```bash
getent passwd dominik
```

Check whether a user exists:

```bash
id username
```

---

## 17. Checking Groups

List groups:

```bash
cat /etc/group
```

Query a specific group:

```bash
getent group docker
```

Check a user's group membership:

```bash
groups username
```

or:

```bash
id username
```

---

## 18. Who Is Currently Logged In?

Show logged-in users:

```bash
who
```

Show more information:

```bash
w
```

You can also use:

```bash
users
```

---

## 19. Switching Users

Switch to another user:

```bash
su - username
```

Switch to root:

```bash
sudo -i
```

Run a single command as another user:

```bash
sudo -u username command
```

Example:

```bash
sudo -u postgres psql
```

This is very useful when administering services.

# Key Things to Remember

### 1. User ≠ Group

```text
User  = a specific user account
Group = a collection of users
```

### 2. UID and GID

```text
UID → user identifier
GID → group identifier
```

Linux uses numeric IDs internally, not just names.

### 3. `sudo`

You do not need to log in as root to perform administrative tasks.

```bash
sudo command
```

### 4. `usermod -aG`

Remember this pattern:

```bash
sudo usermod -aG group username
```

The `-a` is important because it prevents accidentally replacing the user's other supplementary groups.

### 5. `/etc/passwd`, `/etc/shadow`, `/etc/group`

```text
/etc/passwd → user account information
/etc/shadow → password hashes and password aging information
/etc/group   → group information
```

### 6. Principle of Least Privilege

A user or service should have **only the permissions it actually needs**.
